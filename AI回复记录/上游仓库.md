这是一个非常经典且高频的开源场景。你的诉求是：**把自己 fork 仓库的 `main` 弄“脏”了（有不想提交给原作者的更改），现在想从干净的原作者代码基础上，切出一个单独的翻译分支。**

解决这个问题的核心，是引入 **`upstream`（上游仓库）** 的概念。

### 🧠 核心原理：`origin` vs `upstream`
*   **`origin`**：你自己的 Fork 仓库（`nzhijun/d3recipes`）。
*   **`upstream`**：原作者的项目（`原作者/d3recipes`）。

你现在的 `main` 是基于最初 Fork 的代码，并加上了你自己的改动。如果你直接在这个 `main` 上切新分支，那些“不想提交的改动”会跟着过去。**正确的做法是：忽略你当前的 `main`，直接从 `upstream/main` 切出新分支。**

---

### 🚀 具体操作步骤（命令行 + VS Code 双管齐下）

为了操作最精准，建议先在终端敲两行命令完成“连接原仓库”的配置（这是一次性工作，以后就省事了），然后再回到 VS Code 可视化操作。

#### 第一步：关联原作者仓库（终端操作）
打开 VS Code 的终端（`` Ctrl+` `` 或 `` Cmd+` ``），确保当前目录是 `d3recipes`，然后执行：
```bash
# 1. 把原作者的仓库添加为一个叫 upstream 的远程源
git remote add upstream https://github.com/原作者用户名/d3recipes.git

# 2. 拉取原仓库的最新代码（注意：这只会下载，不会覆盖你本地的改动）
git fetch upstream
```
*如果你忘了原作者的用户名，去你 Fork 的仓库页面，点一下 `forked from xxx` 就能看到。*

#### 第二步：基于原作者的最新代码创建分支（VS Code 可视化操作）
1. 在 VS Code 左下角点击当前分支（可能是 `main`）。
2. 在弹出的菜单中选择 **`+ 创建新分支依据...`**（注意：不是“创建新分支”）。
3. 在弹出的顶部输入框里，选择 **`upstream/main`**（这会列在远程分支里）。
4. 接着输入你的新分支名字：**`i18n/update-game-terms`**，回车。
5. 此时左下角会变成 `i18n/update-game-terms`，并且代码已经是**完全干净的原作者最新版本**（你自己在 `main` 上的修改不会带过来）。

#### 第三步：修改、提交并推送
1. 在这个干净的新分支上，打开 `i18n.js`，替换翻译。
2. 提交：暂存 -> 写备注（如 `i18n: 替换AI翻译为实际游戏版本`）-> 提交。
3. 点击 **“发布 Branch”**（因为这是个新分支，需要推送到你的 Fork 仓库）。

#### 第四步：发起 PR
1. 回到 GitHub 网页，进入**你自己的** `nzhijun/d3recipes`。
2. 顶部会提示你刚推送了分支，点击 **`Compare & pull request`**。
3. **关键检查**：在创建 PR 页面上方，确认 `base repository` 是 **原作者**，`base` 是 `main`；`head repository` 是你的 Fork，`compare` 是 `i18n/update-game-terms`。
4. 写清描述，点击 **`Create pull request`**。

### 💡 灵魂拷问解答

**问：我原来 main 分支上那些不想提交的修改去哪了？**
答：它们依然安安静静地待在你的本地 `main` 分支和你 Fork 的 `origin/main` 上。以后你想用它们，就切回 `main`；不想用，就永远放在那里，互不干扰。

**问：以后原作者更新了代码，我想同步怎么办？**
答：只需在终端执行 `git fetch upstream`，然后在 VS Code 里把 `main` 分支的“创建新分支依据”换成 `upstream/main`，重建一个同名分支即可（或者在 GitHub 网页上点你 Fork 仓库的 `Sync fork` 按钮一键同步）。

**问：如果原作者的 PR 合并了，我的翻译也合并了，我这个 `i18n` 分支还要吗？**
答：合并后，直接删掉这个 `i18n` 分支即可，保持仓库清爽。下次有新翻译需求，再按上述步骤开新分支。
